# Contract triangle

DET keeps three related surfaces aligned. Drift between them is the most common
source of “bronze loads but dbt fails” or “schema validates but analytics is wrong.”

## The three layers

| Layer | Where | What it owns |
| --- | --- | --- |
| **Bronze wire contract** | `schemas/<provider>/<source>/*.schema.yaml` | Typed landing validation at extract/load: column types, required fields, `additionalProperties: false`. Lake dataset ids (`{name}_vN`) come from pipeline `wire_version`, not the schema file. |
| **dbt read catalog** | `dbt/models/silver/sources.yml` + scaffolded `stg_*.sql` | Column names and types dbt reads from bronze (`det_bronze_from`, read_json paths). Regenerated by scaffold. |
| **Analytics semantics** | Pipeline YAML `dbt.stg` (+ hand-edited SQL) | Renames, coalesce across wire eras, value maps, null sentinels, excludes, flatten/relations. Example: [`configs/pipelines/example_api/events.yaml`](../configs/pipelines/example_api/events.yaml). |

Bronze is **wire-faithful**. Silver/gold adapt for reporting — prefer `dbt.stg` for
frequent renames; reserve bronze mappers and `wire_version` bumps for true wire breaks.

## When you change something

| Change | Touch | Rebuild / regen |
| --- | --- | --- |
| Wire shape or parse rules | Schema YAML + bump `wire_version` in pipeline YAML | Re-extract or `det migrate` from raw for existing partitions |
| Bronze column set/types (same wire era) | Schema YAML; optional `@mapper` in source plugin | `det migrate` into same or new `--to-bronze` id |
| Analytics-only (rename, coalesce, map) | Pipeline `dbt.stg` knobs | `det scaffold-dbt -p <pipeline> --force` |
| Silver tests / materialization | Pipeline `dbt.silver` | Re-scaffold or hand-edit `silver_*.sql` / `_silver__models.yml` |

## Verify

```bash
det check --strict    # CI runs this; warnings fail the build
```

Under `--strict`, stale scaffold SQL (`scaffold_sql_stale`) and missing dbt models
(`missing_dbt_models`) are errors, not warnings.
